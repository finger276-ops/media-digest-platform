# Сертификаты НУЦ Минцифры для GigaChat

GigaChat отдаёт TLS-сертификат, подписанный Национальным удостоверяющим центром
Минцифры. В системных хранилищах этого корня нет, поэтому запрос падает с
`CERTIFICATE_VERIFY_FAILED: self-signed certificate in certificate chain`.

Платформа решает это точечно: сертификат из этой папки используется **только**
для запросов к GigaChat. В системный список доверенных корней ничего не
добавляется, и на остальные соединения это никак не влияет.

## Как положить сертификат

Из корня репозитория:

```bash
mkdir -p certs
curl -sS -w '\n' https://gu-st.ru/content/lending/russian_trusted_root_ca_pem.crt \
  > certs/russian_trusted_ca.pem
curl -sS -w '\n' https://gu-st.ru/content/lending/russian_trusted_sub_ca_pem.crt \
  >> certs/russian_trusted_ca.pem
```

Нужны **оба** сертификата — корневой и выпускающий: проверка цепочки без
второго не пройдёт. Скачать вручную можно на https://www.gosuslugi.ru/crt.

Файл коммитится в репозиторий: это публичный корневой сертификат, а не секрет.
После коммита Streamlit Cloud подхватит его при следующем деплое, и ничего
настраивать не нужно — платформа сама находит `certs/russian_trusted_ca.pem`.

## Если файл лежит в другом месте

Путь задаётся секретом:

```toml
GIGACHAT_CA_BUNDLE = "/etc/ssl/certs/russian_trusted_ca.pem"
```

## Проверка

Раздел «Отчёт» → «Тексты от ИИ» → кнопка **«Проверить подключение»**. Она делает
один короткий запрос и показывает либо ответ модели, либо причину отказа.

## Крайняя мера

```toml
GIGACHAT_VERIFY_SSL = "false"
```

Проверка сертификата отключается полностью. Соединение остаётся шифрованным, но
подменить сервер становится возможно. Годится как временное решение на время
настройки, не как постоянное.
