# Платформа дайджестов

Это отдельная мультипроектная версия дашборда. Она не использует старые таблицы `dashboard_*` и не смешивает данные с текущим проектом «Дайджест водительских чатов».

## Что уже реализовано

- отдельные таблицы Supabase с префиксом `platform_*`;
- создание нескольких проектов;
- отдельные периоды, файлы, сообщения и инфоповоды внутри каждого проекта;
- доступ через коды проекта:
  - код просмотра;
  - код редактора;
- отдельный пароль владельца платформы;
- загрузка CSV/Excel:
  - Медиалогия CSV/Excel;
  - Brand Analytics CSV/Excel, включая теговые колонки после `Обработано`;
  - универсальный CSV/Excel;
- саммари по выбранным периодам;
- ручное редактирование саммари;
- динамика сообщений и негатива по периодам;
- история периодов с редактированием названия, дат, файла и статуса;
- мультипроектная ручная модерация инфоповодов:
  - ручное создание инфоповода;
  - редактирование названия, описания и тегов;
  - объединение инфоповодов;
  - перенос сообщений между инфоповодами;
  - отметка «нерелевант» для сообщения внутри темы;
  - скрытие сообщений и инфоповодов.

## Как развернуть отдельно от текущего проекта

Создай новый GitHub-репозиторий, например:

```text
media-digest-platform
```

Загрузи туда содержимое этой папки.

В Streamlit Cloud укажи главный файл:

```text
streamlit_app.py
```

## SQL в Supabase

В Supabase открой:

```text
SQL Editor → New query
```

Вставь и выполни содержимое файла:

```text
sql/platform_schema.sql
```

Будут созданы таблицы:

```text
platform_projects
platform_periods
platform_table_rows
platform_manual_rows
platform_project_members
```

Они не пересекаются со старыми таблицами `dashboard_periods`, `dashboard_table_rows`, `dashboard_manual_rows`.

## Secrets в Streamlit Cloud

В настройках приложения добавь:

```toml
SUPABASE_URL = "https://xxxxxxxx.supabase.co"
SUPABASE_SERVICE_ROLE_KEY = "твой_service_role_key"
SUPABASE_STORAGE_BUCKET = "dashboard-csv"
PLATFORM_ADMIN_PASSWORD = "придумай_пароль_владельца"
```

`SUPABASE_STORAGE_BUCKET` можно использовать тот же, потому что файлы платформы сохраняются по пути:

```text
project_id/period_id/file.csv
```

Но для полной изоляции можно создать отдельный bucket, например:

```toml
SUPABASE_STORAGE_BUCKET = "digest-platform-files"
```

## Роли доступа

### Владелец платформы

Входит по `PLATFORM_ADMIN_PASSWORD`. Может:

- создавать проекты;
- редактировать проекты;
- видеть все проекты;
- загружать файлы в любой проект;
- редактировать периоды и саммари.

### Редактор проекта

Входит по коду редактора конкретного проекта. Может:

- загружать файлы;
- редактировать периоды;
- редактировать саммари.

### Просмотр проекта

Входит по коду просмотра. Может:

- смотреть саммари;
- смотреть динамику;
- смотреть инфоповоды и сообщения.

## Первый запуск

1. Войти как владелец платформы.
2. Открыть раздел **Проекты**.
3. Создать проект.
4. Указать код просмотра и код редактора.
5. Перейти в **Загрузка файла**.
6. Загрузить CSV или Excel.
7. После обработки открыть **Дашборд**.

## Как не смешивать данные с текущим дашбордом

Текущий проект использует таблицы:

```text
dashboard_*
```

Платформа использует таблицы:

```text
platform_*
```

Даже если оба приложения подключены к одному Supabase-проекту, данные лежат в разных таблицах.

Для максимальной изоляции можно создать отдельный Supabase-проект только под платформу.


## Специфика Brand Analytics

В выгрузках Brand Analytics после служебной колонки `Обработано` обычно идут теговые колонки системы. Например: `ТЕХНОНИКОЛЬ`, `Теплоизоляция`, `КП`, `Knauf Insulation`, `Маркетплейсы`, `ROCKWOOL`, `PR`, `отзыв` и т.д.

Платформа сохраняет эти колонки при импорте и использует их как первичные сигналы для формирования тегов, тем, инфоповодов и аналитики. Это важно для бренд-мониторинга: тема должна собираться не только по словам из текста, но и по разметке Brand Analytics.

## Обновление 3.2: универсальные темы проектов

Платформа больше не использует такси-словарь как базовый профиль. Алгоритм обработки теперь строит темы и теги в первую очередь из самой выгрузки:

- `Сюжет`;
- `Теги`;
- `Категории`;
- `Основная тема`;
- `Все темы`;
- `Все темы (список)`;
- бинарные проектные колонки вида `Да/Нет`, `True/False`, `1/0`, `+/-`.

Такси-правила сохранены только как legacy-профиль для старых проектов с водительскими чатами. Для новых проектов по умолчанию используется универсальный профиль.

Также исправлен импорт Excel:

- пустые листы пропускаются;
- лист `Сообщения` выбирается приоритетно;
- поддержаны файлы с раздельными колонками `Дата` и `Время`;
- поддержаны колонки `Hash сообщения`, `ID сообщения`, `Источник`, `Url`, `Тип источника`, `Место публикации`, `Url места публикации`.
