# Индексы бренда: что считает платформа

Раздел **Дашборд → Индексы бренда** автоматически считает метрики из
Metric Calculation Guide. Формулы и входные числа раскрываются под карточками,
поэтому любую цифру можно проверить вручную.

## Откуда берутся данные

| Понятие гайда | Колонка выгрузки | Поле платформы |
| --- | --- | --- |
| Охват | «Просмотры» / «Просмотров» / «Охват» | `views` |
| Аудитория (подписчики) | «Аудитория» | `audience` |
| Реакции | «Лайки» + «Комментарии» + «Репосты» | `likes`, `comments`, `reposts` |
| Реакции (запасной вариант) | «Вовлечённость» | `engagement` |
| Тональность | «Тональность» / «Окраска» / «Тон» | `sentiment` |
| Инфоповод | «Сюжет» (Brand Analytics) или результат кластеризации | `event_title` |

Если отдельных колонок лайков, комментариев и репостов в выгрузке нет, реакции
берутся из сводной колонки «Вовлечённость» — в расшифровке метрики всегда
написано, какой источник использован.

Если в выгрузке нет просмотров (типично для СМИ-выгрузок), SES считается по
аудитории, и это тоже отмечается в расшифровке.

## Метрики

| Метрика | Формула | Нужны данные |
| --- | --- | --- |
| **SES** | (Позитивный охват − Негативный охват) / Общий охват × 100 % | охват, тональность |
| **NSS** | % позитивных инфоповодов − % негативных инфоповодов | тональность, инфоповоды |
| **ToneVolumeScore** | (Позитивные − Негативные) / Все упоминания × 100 % | тональность |
| **ER** | Реакции / Подписчики × 100 % | реакции, аудитория |
| **ERR** | Реакции / Охват × 100 % | реакции, охват |
| **SOV** | Показатель бренда / Показатель всех брендов × 100 % | выгрузка по категории |
| **ReachScore** | Охват бренда / Максимальный охват в категории × 100 % | выгрузка по категории |
| **BPI** | Σ (вес × метрика), веса нормализуются | входящие метрики |

Метрика, для которой не хватает данных, показывает прочерк и текст с причиной —
платформа не подставляет нули вместо неизвестных значений.

## Два расхождения в исходном гайде и как они разрешены

**NSS и ToneVolumeScore по формулам гайда совпадают.** `% позитивных − % негативных`
и `(Позитивные − Негативные) / Все упоминания` — это одно и то же число. Но
расшифровка NSS говорит про **инфоповоды**, а ToneVolumeScore — про упоминания.
Поэтому платформа считает:

- **NSS — по инфоповодам.** Тональность темы определяется большинством: если
  негативных сообщений в теме больше позитивных, тема негативная. Метрика
  отвечает на вопрос «какой повестки больше — хорошей или плохой».
- **ToneVolumeScore — по сообщениям.** Отвечает на вопрос «какого потока больше»
  и учитывает, что одна громкая тема может перевесить десяток тихих.

Так метрики перестают дублировать друг друга. Разница между ними тоже
информативна: если NSS положительный, а ToneVolumeScore отрицательный, значит
негатив сконцентрирован в одной-двух больших темах.

Если нужно поведение ровно по примерам гайда, в настройках раздела можно
переключить NSS на расчёт по сообщениям — тогда обе метрики совпадут.

**У SOV формула и пример расходятся.** Формула написана через охват
(«Охват бренда / Охват всех брендов»), а пример посчитан по упоминаниям
(1 000 / 10 000 = 10 %). Платформа считает оба варианта: основной задаётся в
настройках (по умолчанию по упоминаниям, как в примере), второй показывается в
расшифровке метрики.

## Настройка BPI

По умолчанию BPI собирается как в гайде: NSS × 0,4 + SES × 0,4 + ToneVolumeScore × 0,2.
В настройках раздела можно изменить состав и веса — добавить SOV, ReachScore, ER,
ERR. Веса нормализуются автоматически, поэтому:

- задавать их можно в любых пропорциях, сумма приводится к единице;
- если метрики не хватило данных, она исключается, а веса пересчитываются между
  оставшимися — индекс не обнуляется из-за одного пробела в выгрузке.

Настройки хранятся в `platform_projects.settings.brand_metrics` и действуют
только для своего проекта.

**Предупреждение о шкалах.** SES, NSS и ToneVolumeScore живут в диапазоне
−100…100, а SOV, ReachScore, ER и ERR — в 0…100. Смешивать их в одном индексе
можно (гайд это допускает), но тогда значение BPI сравнимо только между
периодами одного проекта, а не с внешними бенчмарками. Интерфейс показывает это
предупреждение при сохранении такой конфигурации.

## Выгрузка по категории для SOV и ReachScore

Эти две метрики сравнивают бренд с конкурентами, поэтому данных одного проекта
недостаточно. В разделе «Индексы бренда» есть блок **«Выгрузка по категории»**:

1. Выгрузите из Brand Analytics данные по всей категории — своему бренду и конкурентам.
2. Загрузите файл и укажите период, к которому он относится.
3. Выберите, как в файле различаются бренды:
   - **каждый бренд — отдельная колонка** (обычный вариант Brand Analytics: колонки
     после служебной «Обработано»);
   - **название бренда в одной колонке** — тогда платформа сгруппирует по значениям.
4. Отметьте, какой из брендов ваш, и сохраните.

Платформа сохраняет **только агрегаты по брендам** — количество сообщений,
аудиторию, охват и вовлечённость. Сообщения конкурентов в базу не попадают,
поэтому категорийная выгрузка на сотни тысяч строк превращается в десяток чисел.

Таблица: `platform_category_benchmarks`, схема — `sql/platform_brand_metrics_schema.sql`
(выполнить один раз в Supabase SQL Editor).

## Динамика

При выборе двух и более периодов раздел строит график изменения индексов по
периодам и таблицу значений. Метрики на графике выбираются галочками; по
умолчанию показываются BPI, NSS и SES.

## Что стоит помнить при интерпретации

- **ER считается от суммарной аудитории площадок**, а не от подписчиков бренда:
  в выгрузке мониторинга «Аудитория» — это размер площадки, где вышло сообщение.
  Метрика корректна для сравнения периодов между собой, но это не ER собственного
  аккаунта из статистики соцсети.
- **Одно сообщение может относиться к нескольким брендам** в категорийной
  выгрузке, поэтому сумма по брендам может превышать общее число сообщений в
  файле. Для долей это нормально и соответствует практике категорийного
  мониторинга.
- **Высокий SOV не всегда хорош.** Он показывает громкость, а не качество:
  всплеск негатива тоже поднимает долю голоса. Смотрите его рядом с NSS и SES.
