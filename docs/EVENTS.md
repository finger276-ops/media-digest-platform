# Как платформа собирает инфоповоды

Инфоповод — это группа сообщений об одном событии. У платформы два источника
такой группировки, и они работают по-разному.

## Откуда берутся границы события

| Тип выгрузки | Что группирует сообщения | Заголовок |
| --- | --- | --- |
| Brand Analytics | колонка «Сюжет» — готовая группировка источника | текст сюжета |
| Медиалогия, универсальный CSV | TF-IDF-кластеризация текстов в узком окне по теме и времени | собирается из ключевых слов |

Для Brand Analytics платформа **не кластеризует** сообщения заново: источник уже
сделал эту работу, и переклеивать её означало бы терять редакторскую разметку.

## Три ступени склейки

### 1. Один период: сюжет → инфоповод

При обработке выгрузки каждый уникальный сюжет получает `event_id`, посчитанный
от **нормализованной** формы заголовка. Разные написания одного сюжета
(«ТЕХНОНИКОЛЬ…» / «Технониколь…», с кавычками и без) дают один идентификатор.
Название инфоповода остаётся исходным: показывается формулировка, за которой
больше сообщений.

### 2. Несколько периодов: заголовок как единственная связь

При загрузке `event_id` получает префикс периода, иначе идентификаторы из
разных выгрузок столкнулись бы между собой. Побочный эффект: **между периодами
события связывает только текст заголовка**. Brand Analytics переформулирует
сюжеты от недели к неделе, поэтому одна тема может разъехаться на несколько
инфоповодов.

Поэтому при сборке дашборда заголовки нормализуются ещё раз: регистр, ё/е,
кавычки и тире всех начертаний, многоточия, пробелы внутри чисел, пунктуация.
Эта ступень включена всегда и ничего лишнего не склеивает — она убирает только
косметические различия.

### 3. Смысловая склейка близких заголовков

Ступень, которую можно настроить: «⚙️ Вид» → «Склейка похожих заголовков».

| Режим | Порог | Когда нужен |
| --- | --- | --- |
| Выключено | — | источник даёт стабильные формулировки, нужна буквальная картина |
| Осторожно | 0,75 | склеиваются только почти дословные совпадения |
| Обычно | 0,62 | значение по умолчанию |
| Агрессивно | 0,5 | источник сильно переписывает заголовки между периодами |

Как считается похожесть: заголовок раскладывается на значимые слова (без
стоп-слов и голых чисел), слова приводятся к грубой основе, каждое получает вес
по IDF — слово, которое есть в каждом заголовке, почти ничего не значит.
Похожесть — доля общего веса в общем объёме.

Три ограничения делают склейку консервативной:

- заголовки короче трёх значимых слов объединяются только при точном совпадении
  нормализованной формы;
- нужно минимум два общих значимых слова;
- склейка идёт **к лидеру группы, а не по цепочке**: каждый участник похож
  непосредственно на самую крупную тему, поэтому «A похож на B» и «B похож на C»
  не делают A и C одним инфоповодом.

Отдельное правило ловит усечённые заголовки: если короткий почти целиком
содержится в длинном («…на выставке» и «…на выставке в Москве»), это одна тема.

## Как проверить и отменить

- Над таблицей инфоповодов — блок **«Склеено похожих заголовков: N»** со списком
  вариантов под каждым сюжетом.
- **«Не склеивать»** рядом с вариантом навсегда выводит этот заголовок из
  автосклейки. Вернуть — в блоке «Заголовки без автосклейки».
- В таблице рядом с названием стоит **«(+2)»**: столько формулировок собрано под
  этим сюжетом.
- **«Проверить, сколько заголовков дублируется»** считает на текущих данных,
  сколько инфоповодов останется при каждом пороге, — чтобы решение принималось
  по своей выгрузке, а не на глаз.

Автоматика не заменяет ручную модерацию: «Объединить с темой» в правке
инфоповода по-прежнему работает и выполняется раньше автосклейки.

Ручные правки тоже отменяются. Блок **«Ручные правки инфоповодов: N»** под
«Создать инфоповод вручную» перечисляет скрытые темы, объединения и
перенесённые сообщения, у каждой — кнопка «Отменить». Скрытая тема
возвращается с прежними правками названия, описания и тегов. Блок виден, даже
если в периоде не осталось ни одной темы: именно тогда он и нужен.

После объединения счётчики не складываются дважды: у темы-источника они
обнуляются, а её сообщения, негатив и площадки считаются у цели.

## Порядок операций

```
выгрузка → сюжет/кластер → event_id (нормализованный заголовок)
        → ручные правки и объединения
        → нормализация заголовков
        → смысловая склейка близких заголовков
        → порог «мин. сообщений в инфоповоде»
        → дашборд, саммари, отчёты
```

Склейка идёт **до** порога по числу сообщений. Иначе тема, разбитая источником
на три формулировки по два сообщения, отсекалась бы как мелочь, хотя вместе это
шесть сообщений.
