# Резервные копии

Все данные платформы — проекты, периоды, обработанные таблицы, ручные правки
аналитиков — живут в одной базе Supabase. Бесплатный тариф Supabase хранит свои
бэкапы недолго и восстанавливает их только целиком, поэтому у платформы есть
свои копии.

## Что копируется

Таблицы `platform_projects`, `platform_periods`, `platform_table_rows`,
`platform_manual_rows`, `platform_project_members`, `platform_tag_hierarchies`,
`platform_ingest_sources`, `platform_ingest_queue`,
`platform_category_benchmarks`, `platform_audit_log` (журнал правок). Таблица, которой нет в базе (миграция не
накачена), пропускается и записывается в манифест копии.

Не копируются: присутствие в сессиях (`platform_sessions`) — это живые отметки
«кто сейчас на странице»; служебная таблица миграций; исходные файлы выгрузок —
они и так лежат в хранилище.

Копия — zip: `manifest.json` и по файлу JSON Lines на таблицу.

## Где лежат копии и сколько хранятся

- **Хранилище Supabase**, папка `backups/`, имя `platform_ГГГГ-ММ-ДД_ЧЧММСС.zip`
  (время UTC). Хранятся 14 последних, более старые удаляются при каждой новой
  копии. Последняя не удаляется никогда.
- **Артефакт GitHub Actions** запуска «Резервная копия» — копия вне Supabase на
  случай, если потеряется сам проект Supabase. Хранится 7 дней.

Копию делает задача `.github/workflows/backup.yml` каждую ночь в 03:17 UTC
(06:17 МСК). Её можно запустить вручную: GitHub → Actions → «Резервная копия» →
Run workflow. Ещё один способ — кнопка «Сделать копию сейчас» в блоке
«Резервные копии» на странице «Проекты» (только владелец).

Задаче нужны те же секреты репозитория, что и автозагрузке:
`SUPABASE_URL`, `SUPABASE_SERVICE_ROLE_KEY`, `SUPABASE_STORAGE_BUCKET` — см.
«Секреты GitHub» ниже.

## Секреты GitHub

Секреты Streamlit Cloud и секреты GitHub Actions — разные хранилища: приложение
на Streamlit работает, а задачи GitHub (резервная копия, автозагрузка) без своих
секретов падают с аннотацией «Не заданы секреты репозитория».

1. Откройте репозиторий на GitHub → **Settings** → **Secrets and variables** →
   **Actions** → **New repository secret**.
2. Добавьте по одному:
   - `SUPABASE_URL` — адрес проекта Supabase, вида `https://xxxx.supabase.co`;
   - `SUPABASE_SERVICE_ROLE_KEY` — ключ `service_role`;
   - `SUPABASE_STORAGE_BUCKET` — имя бакета хранилища, если в секретах
     Streamlit он задан; если нет — этот секрет не нужен (по умолчанию
     `dashboard-csv`).

   Значения те же, что в Streamlit Cloud → приложение → **Settings** →
   **Secrets**. Их же можно взять в Supabase → **Project Settings** → **API**.
3. Запустите «Резервная копия» вручную: **Actions** → «Резервная копия» →
   **Run workflow**. Зелёный запуск и артефакт `platform-backup-…` в нём —
   значит, всё настроено.

Блок «Резервные копии» предупреждает, если последней копии больше двух суток.
Частая причина — GitHub отключает расписание в репозитории, где 60 дней не было
изменений: включить обратно можно на странице задачи в Actions.

## Восстановление

Восстановление — только из командной строки: это действие над всей базой.
Строки записываются поверх по первичному ключу: существующие перезаписываются
данными копии, строки, которых в копии нет, остаются. Нужны переменные
окружения `SUPABASE_URL` и `SUPABASE_SERVICE_ROLE_KEY`.

```bash
# какие копии есть
python scripts/backup_platform.py list

# что будет восстановлено из последней копии — только подсчёт
python scripts/backup_platform.py restore --dry-run

# восстановить один проект из конкретной копии
python scripts/backup_platform.py restore \
  --storage backups/platform_2026-09-27_031700.zip --project taxi_project

# восстановить всё из файла (например, скачанного артефакта GitHub)
python scripts/backup_platform.py restore --file platform-backup.zip
```

Журнал правок восстанавливается, только если в базе (при `--project` — у
этого проекта) он пуст: у записей журнала нет естественного ключа, и повторное
восстановление задвоило бы их.

Без `--yes` скрипт показывает, сколько строк запишет, и спрашивает
подтверждение. После восстановления откройте платформу заново: кеш страниц
живёт до 15 минут.

Сделать копию вручную из командной строки:

```bash
python scripts/backup_platform.py backup --keep 14 --out copy.zip
```

Код — `services/backups.py`, проверка полного круга «копия → очистка →
восстановление» — `tests/test_backup.py`.
