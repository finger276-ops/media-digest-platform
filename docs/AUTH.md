# Вход по email

Человек вводит рабочий адрес, получает письмо с кодом, вводит код — и видит
проекты, к которым ему выдан доступ. Вход запоминается в этом браузере на
14 дней: обновление страницы, новая вкладка и передеплой платформы не
требуют нового письма. «Выйти» отзывает запомненный вход сразу.

Коды проектов работают как раньше, пароль владельца — тоже: это аварийный
вход на случай, если почта или Supabase Auth недоступны.

## Кто что может

| Кто | Как входит | Что видит |
|---|---|---|
| Владелец платформы | адрес из `PLATFORM_OWNER_EMAILS` или пароль `PLATFORM_ADMIN_PASSWORD` | все проекты, «Проекты», «Сессии» |
| Аналитик | адрес с ролью «Аналитик» в проекте или код аналитика | свой проект: данные, загрузка, настройки |
| Пользователь | адрес с ролью «Пользователь» или код пользователя | аналитику проекта, отчёт |

Доступ по email выдаёт **только владелец платформы**: «Проекты» → выбрать
проект в таблице → блок **«Доступ по email»**. Там же меняется роль и
закрывается доступ. Аналитик видит этот список в «Настройках проекта», но не
меняет его.

У одного адреса может быть несколько проектов с разными ролями — в боковой
панели появится выбор проекта. Аналитик, вошедший по email и заведший новый
проект, сразу получает к нему доступ аналитика.

Снятый доступ закрывается и в уже открытой вкладке — не позже чем через
минуту (столько живёт кеш списка доступа).

## Настройка — один раз

### Шаг 1. Миграция

В Supabase **SQL Editor** выполнить `sql/migrations/0007_platform_email_auth.sql`.
Она создаёт таблицы запомненных входов и ограничителей и закрывает RLS
список доступа (приложение ходит служебным ключом и этого не замечает).

### Шаг 2. Почта в Supabase

Встроенная почта Supabase **не подходит**: она шлёт письма только участникам
команды проекта Supabase и не больше двух в час. Нужен свой SMTP.

**Authentication → Emails → SMTP Settings → Enable custom SMTP**:

| Сервис | Host | Порт | Логин | Пароль |
|---|---|---|---|---|
| Unisender Go (для рассылок из сервисов, лучший вариант) | `smtp.go1.unisender.ru` или `smtp.go2.unisender.ru` — по адресу вашего кабинета | 587 или 465 | user_id или project_id | API-ключ |
| Яндекс 360 | `smtp.yandex.ru` | 465 | адрес ящика | пароль приложения |
| Mail.ru / VK WorkMail | `smtp.mail.ru` | 465 | адрес ящика | пароль приложения |

Отправитель — адрес на вашем домене с настроенными SPF и DKIM, иначе письма
будут падать в «Спам». Ящики Яндекса и Mail.ru годятся для небольшого числа
пользователей; для десятков людей лучше транзакционный сервис.

**Authentication → Rate Limits**: после подключения своего SMTP лимит —
30 писем в час на весь проект. Поднимите его под число пользователей.

### Шаг 3. Шаблон письма: код вместо ссылки

**Authentication → Emails → Templates → Magic Link**. Ссылку
`{{ .ConfirmationURL }}` заменить на код `{{ .Token }}`, например:

```html
<h2>Вход в платформу дайджестов</h2>
<p>Ваш код для входа: <strong style="font-size: 20px">{{ .Token }}</strong></p>
<p>Код действует несколько минут. Если вы не запрашивали вход, просто проигнорируйте письмо.</p>
```

Тема: «Код для входа в платформу».

Почему именно «Magic Link»: платформа сама заводит пользователя Supabase
уже подтверждённым и просит код без регистрации — Supabase в этом случае
шлёт этот шаблон. Ссылки не используются намеренно: Streamlit не может их
прочитать, корпоративные почтовые фильтры «открывают» ссылки заранее и
сжигают их, а сам адрес `*.supabase.co` у части российских провайдеров
открывается с перебоями. Код человек просто переписывает — браузер в
Supabase не ходит вообще.

### Шаг 4. Срок и длина кода, регистрация

**Authentication → Sign In / Providers → Email**:

- **Email OTP Expiration** — 600 секунд (10 минут) достаточно; по умолчанию час.
- **Email OTP Length** — любая от 6 до 10: платформа принимает любую длину.
- **Allow new users to sign up** — можно выключить. Пользователей заводит
  платформа служебным ключом, и только для адресов из списка доступа.

### Шаг 5. Секреты Streamlit

```toml
EMAIL_LOGIN_ENABLED = "true"
PLATFORM_OWNER_EMAILS = "you@agency.ru, partner@agency.ru"
```

`PLATFORM_OWNER_EMAILS` — строка через запятую (не массив TOML).
`PLATFORM_ADMIN_PASSWORD` оставьте: это вход на случай, если почта не
работает.

Пока `EMAIL_LOGIN_ENABLED` не включён, формы входа по email нет, а список
доступа можно готовить заранее — он заработает, когда вход включат.

Если пароль владельца не задан, раньше режим владельца был открыт всем.
Теперь, когда вход по email включён и адреса владельцев заданы, этого больше
нет: владелец — только тот, кто вошёл со своего адреса. Без адресов
владельцев поведение прежнее (на нём держится локальная песочница).

### Шаг 6. Проверить

1. Выдать доступ своему второму адресу с ролью «Пользователь».
2. Открыть платформу в другом браузере или в режиме инкогнито, войти с этого
   адреса. Проверить, что виден только нужный проект.
3. Обновить страницу — вход должен сохраниться.
4. Нажать «Выйти», обновить страницу — должна появиться форма входа.

Всё это стоит сначала пройти на staging (`docs/STAGING.md`): там свой проект
Supabase, и настройки почты из шагов 2–4 повторяются и для него.

## Что защищено и как

- **Код уходит только своим.** Письмо получают адреса из списка доступа
  действующих проектов и владельцы. Ответ на экране для чужого адреса тот же
  («если адрес есть в списке, код отправлен») — перебором нельзя узнать, чьи
  адреса есть в платформе.
- **Пять неверных кодов закрывают код.** Supabase сам таких попыток не
  считает, а все запросы идут с одного адреса сервера Streamlit. После пяти
  ошибок нужен новый код; старый не примется, даже верный.
- **Частота писем:** не чаще раза в минуту и не больше пяти в час на адрес.
- **В браузере — не токены.** В cookie лежит случайный ключ, в базе — только
  его хеш, адрес и срок. Утечка таблицы не даёт войти.
- **Выход отзывает ключ на сервере**, даже если браузер не успел стереть
  cookie.
- **Адреса не уходят в уведомления о сбоях** (вебхук, Sentry) — только тип и
  код ошибки.
- **Счётчики попыток хранят хеш адреса**, а не сам адрес: запись заводится и
  для чужих адресов, хранить их открытым текстом незачем.

Ограничения, о которых стоит знать:

- cookie ставится скриптом страницы, поэтому он не `HttpOnly`: скрипт,
  попавший на страницу, мог бы его прочитать. Streamlit не даёт поставить
  серверный cookie без экспериментального API. Вред ограничивают срок
  14 дней и отзыв по «Выйти».
- Все запросы к Supabase Auth идут с сервера Streamlit, поэтому лимиты
  Supabase по IP (30 запросов кода и 30 проверок за 5 минут) общие на всех.
  Для десятков пользователей этого хватает.
- Приложение по-прежнему ходит в базу служебным ключом и проверяет доступ
  само. RLS с токеном пользователя — следующий шаг.

## Персональные данные

Адреса сотрудников — персональные данные. Они лежат в Supabase: в списке
доступа, в `auth.users` и в запомненных входах. С 1 июля 2025 года
152-ФЗ (ч. 5 ст. 18 в новой редакции) запрещает первичный сбор и хранение
персональных данных граждан РФ в базах за пределами России, а Supabase и
Streamlit Cloud — зарубежные сервисы. До того как раздавать доступ
сотрудникам клиентов, это стоит обсудить с юристом.

## Если не работает

| Что видно | Что проверить |
|---|---|
| «Вход по email пока не готов…» | не применена миграция 0007 |
| Письмо не приходит | SMTP (шаг 2), папка «Спам», Rate Limits, **Authentication → Logs** в Supabase |
| Пришла ссылка, а не код | в шаблоне Magic Link осталась `{{ .ConfirmationURL }}` (шаг 3) |
| «Не удалось отправить письмо» | владельцу приходит уведомление с типом ошибки (если настроены `ALERT_WEBHOOK_URL` или Sentry) |
| «Почта платформы упёрлась в лимит» | Authentication → Rate Limits |
| Код не подходит | код просрочен или запрошен новый — действует только последний |
| Нет формы входа по email | `EMAIL_LOGIN_ENABLED = "true"` в секретах |

## Где в коде

- `src/services/email_login.py` — отправка и проверка кода, ограничители.
- `src/services/login_sessions.py` — запомненный вход.
- `src/auth_ui.py` — форма входа, «Выйти», cookie.
- `src/project_admin_ui.py` — выбор проекта по списку доступа.
- `src/members_ui.py` — блок «Доступ по email».
- `src/platform_store.py` — список доступа (`platform_project_members`).
- `tests/test_email_login.py` — всё перечисленное выше.
