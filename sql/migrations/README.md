# Миграции схемы

До этой папки схема применялась вручную — отдельными файлами `sql/*.sql`, без
записи о том, что уже применено. Итог: на проде так и осталось неизвестным,
накатан ли `platform_sessions_schema.sql` (раздел «Платформа → Сессии»
работает без него молча — если таблицы нет, панель просто не покажет
онлайн-пользователей, ошибки на экране не будет).

## Как применить

1. Открой в Supabase **SQL Editor → New query**.
2. Выполни `0000_schema_migrations.sql` — один раз, создаёт журнал миграций.
3. Выполни файлы `0001…` по порядку номеров, каждый в отдельном запросе.

Все файлы идемпотентны (`create table/index if not exists`) и каждый сам
записывает себя в `schema_migrations` последней строкой. Поэтому если
неизвестно, что уже применялось на конкретной базе, — **безопасно выполнить
все файлы по порядку ещё раз**: то, что уже есть, DDL не тронет, а запись в
журнале не задвоится (`primary key` на `version`).

## Проверить, что применено

```sql
select version, name, applied_at
from public.schema_migrations
order by version;
```

Если в списке нет `0006` — выполни `0006_platform_sessions_schema.sql`.
Если нет `0007` — выполни `0007_platform_email_auth.sql`; без неё не работает
вход по email (`docs/AUTH.md`), остальная платформа работает.

## Добавить новую миграцию

Новый файл `000N_короткое_имя.sql` со следующим номером. Правила:

- DDL идемпотентен: `create table if not exists`, `create index if not exists`,
  `alter table ... add column if not exists`. Файл может понадобиться выполнить
  повторно на другой базе — он не должен падать на уже применённой схеме.
- Последняя строка — запись в журнал:
  ```sql
  insert into public.schema_migrations (version, name)
  values ('000N', 'короткое_имя')
  on conflict (version) do nothing;
  ```
- Существующие файлы не редактируются: они уже могли выполниться на чьей-то
  базе в исходном виде. Изменение схемы — всегда новый файл.

## Откуда взялись файлы 0001–0006

Перенесены без изменения содержимого из `sql/*.sql` в корне репозитория
(остались там же для истории). Порядок — по зависимостям внешних ключей:
`platform_projects` (0002) создаётся раньше всего, что на него ссылается
(0003–0006).
